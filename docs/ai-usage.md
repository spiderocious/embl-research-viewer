# AI-assisted development reflection

**Tools used.** I used Claude Code for scaffolding the Vite + TypeScript project, drafting components and tests, and reviewing some diffs. I used it the way the exercise invites: to move faster on the parts that are mechanical, while keeping the technical decisions and the final code mine. Before writing anything, I used it to probe the Europe PMC API against the live endpoint so the design rested on verified behaviour rather than assumptions.

**A suggestion I took.** When I described the "next / previous" requirement, the suggestion was to use TanStack Query's `useInfiniteQuery` and keep a small page pointer over the cached pages, rather than hand-roll a cursor stack. That fit the forward-only nature of the Europe PMC cursor well: fetch forward, move the pointer back for "Previous" so it never re-requests a page already seen. I took it because it removed state I would otherwise have had to keep in sync by hand, and it is easy to explain.

**A suggestion I corrected.** The first error-state test and handler assumed the API would reject a malformed or empty query with a non-2xx status. I had already checked the live API and knew it returns HTTP 200 for both, so the only real failure mode is a network error. I rewrote the error handling and its test around a failed request (and guard empty queries on the client before any request is made) rather than around the API rejecting input. I also corrected a test environment issue where jsdom's `fetch` rejected React Query's `AbortSignal`; the fix was to pin `fetch` to one realm in the test setup, not to weaken the production client.

**How I verified the application.** The unit and component tests run on Vitest with React Testing Library and MSW, covering query construction, forward/backward navigation (asserting that "Previous" does not refetch), and the API-failure path — ~100% of lines and 97% of branches. On top of that I wrote an end-to-end smoke test that drives the real screen against the **live** Europe PMC API, confirming that `cancer AND immunotherapy NOT melanoma` returns real results with correct article links and that pagination advances against the real cursor. TypeScript runs strict with no `any`, and the production build passes.
